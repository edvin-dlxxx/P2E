## Project in one screen
- Flutter 3.47.7 / Dart 3.13. Product app at root; reusable `p2e_design_system` in `packages/design_system`; independent viewer in `apps/design_system_viewer` (D-019). Riverpod 3 and go_router are installed for the Entry foundation (D-037–D-042).
- Layers: `lib/app` · `lib/core` · `packages/design_system/lib/src` (Design System) · `lib/shared` · `lib/features`.
  Structure, layers, state and routing: `docs/architecture/` (Architecture v1.3 + Addendum v1.4).
  Baseline reports on Figma contents (identity contract, components, typography, icons, colors): `docs/reference/`.
- Themes: Light and Dark both ship in the MVP. Default theme = follow the OS; the user can pick System / Light / Dark.
- Languages: English is built first. Persian (RTL, Jalali dates, Persian digits) comes later, but every UI must already work in RTL.
  D-041 provisionally defaults the product to `fa`, with `en` available through generated localization. No language-picker screen ships yet.
- Size classes by width only: Compact < 600, Medium 600–839, Expanded ≥ 840. Phones are portrait-only; tablets allow both orientations.
- iOS and Android look, animate and behave the same.

## Source of truth
Each source owns a domain. Only the register can override another source; reference reports never override anything.
1. **Figma** decides appearance: colors, typography, icons, sizes, spacing, radii, variants, states.
   File key and node ids: `docs/agents/figma-map.md`. Read values from the latest snapshot in `design/figma/LATEST`.
2. **Architecture v1.3 + Addendum v1.4** (`docs/architecture/`) decide structure (layers, state, routing, testing).
   Where the Addendum contradicts v1.3, the Addendum wins.
3. **`docs/agents/registers/decisions.md`** records everything decided after those documents. A newer decision wins.
4. **Reference reports** (`docs/reference/`) are evidence and proposals, **not decisions**. See "Reference reports" below.

When Figma contradicts itself (a typo, a missing Light/Dark twin, a one-off value), do not copy the mistake.
Log it in `docs/agents/registers/errata.md` and ask the owner.
When Figma says nothing about behavior (loading, error, empty state, keyboard, focus, motion timing), propose an option,
wait for approval, then record it in `decisions.md`. Never invent a design silently.

## Non-negotiable rules
1. **Figma is read-only.** Never call Figma tools that write: `use_figma` with mutating code, `generate_*`, `upload_assets`,
   `create_new_file`, `add_code_connect_map`, `send_code_connect_mappings`, `send_code_to_figma`, `create_*`/`update_*`.
   Read with `get_metadata`, `get_variable_defs`, `get_design_context`, `get_screenshot`, `download_assets`,
   `search_design_system`, or the read-only scripts in `tool/figma/`.
2. **No raw visual values outside `lib/ui/tokens/`.** No `Color(0x…)`, `Colors.*`, hex strings, literal font sizes, literal
   paddings, radii or durations in `lib/ui/components`, `lib/ui/overlays`, `lib/ui/patterns`, `lib/shared/widgets` or `lib/features`.
   Choosing a different existing token is allowed. A raw value is an **override**: annotate it `// OVERRIDE(O-###): reason`
   and register it in `docs/agents/registers/overrides.md`.
3. **Directional layout only.** Use `EdgeInsetsDirectional`, `AlignmentDirectional`, `BorderRadiusDirectional`,
   `PositionedDirectional`, `TextAlign.start/end`. A physical left/right needs `// PHYSICAL: reason`.
4. **Component parameters mirror Figma variant axes as Dart enums** (typos corrected; raw Figma names kept in the spec).
   No `Color`, `TextStyle`, `EdgeInsets` or size `double` parameters for visual choices. Only combinations that exist in Figma
   are valid; an invalid combination asserts in debug. Light/Dark is never a parameter: components read the theme.
5. **Every public Design System widget carries an `ElementIdentity`** (component id, variant values, Figma node id,
   status `final` | `provisional`) and has a spec entry. Widgets without a Figma design are `provisional`.
6. **Features compose; they do not style.** `lib/features/**` uses `lib/ui` components and `lib/shared/widgets` only. Banned in features
   (v1.3 §15.3): `ElevatedButton`, `FilledButton`, `OutlinedButton`, `TextButton`, `IconButton`, `TextField`, `TextFormField`,
   `Card`, `Chip`*, `Switch`, `SwitchListTile`, `Checkbox`, `Radio`, `AlertDialog`, `showDialog`, `showModalBottomSheet`, `SnackBar`, `AppBar`.
7. **Same behavior on iOS and Android.** No `Platform.isX`, `dart:io` or `defaultTargetPlatform` branching in `lib/ui`, `lib/shared`
   or `lib/features`. Platform differences live only in `lib/app/platform` and need an id from
   `docs/agents/registers/platform-exceptions.md` (`// PLATFORM(PE-###): reason`). Page transitions and scroll behavior are
   set once in `lib/app`; per-platform behavior built into Flutter widgets (text selection, keyboard) is accepted.
8. **Icons come only from the Figma SVG exports** in `packages/design_system/assets/icons/system/` through the `AppIcon` input
   (`AssetAppIcon(AppIconId.x)` for the scoped local renderer).
   Never `Icons.*`, `CupertinoIcons.*` or an icon package.
9. **Fonts are bundled.** No runtime font download. Latin: Outfit (from Figma). Persian: Vazirmatn as a provisional fallback until
   the designer defines Persian typography.
10. **No hard-coded user-visible strings.** Every string goes through `l10n/` ARB files (`app_en.arb` now, `app_fa.arb` later).
11. **Dev tools never reach product builds.** Gallery, verification, dev strings and diagnostic specs live in
    `apps/design_system_viewer`. Both apps consume `package:p2e_design_system/design_system.dart`; consumers never import `src/`.
    The package depends on neither app. Product uses root `lib/main.dart`; viewer uses its own `lib/main.dart` (D-019).
12. **Generated files are never edited by hand:** `*.g.dart`, `*.freezed.dart`, `packages/design_system/lib/src/tokens/generated/**`,
    `packages/design_system/lib/src/tokens/specs/generated/**`, `apps/design_system_viewer/lib/specs/generated/**`,
    `.claude/skills/p2e-*`, `.cursor/rules/p2e-*`, `.claude/rules/p2e-*`, `.agents/rules/p2e-*`. Regenerate them from their source.
13. **Text scaling** is supported up to 2.0× and clamped above that (D-044); only App Bar text and Navigator labels use the named component-local 1.3 chrome cap. The Inspector compares against Figma at 1.0×.

## Reference reports (`docs/reference/`)
Baseline reports taken from the Figma file on 2026-10-19. Read `docs/reference/README.md` first. They give detail the rules
only summarize. Open the one that matches your task; do not read all of them.

| Task | Open |
|---|---|
| Generating tokens (colors, text styles, icons) | `colors/`, `typography/`, `icons/` |
| Contract or build of a Design System component | `components/` (Foundation Specification, decision register) and `identity/` |
| `ElementIdentity`, Dev Inspector, fix requests | `identity/` (Contract v1.1, JSON schemas and examples) |
| Building a screen | `typography/` usage map, `components/` |
| Choosing or adding an icon | `icons/` registry (`icon_id`, raw Figma name, node ids) |

How to use them:
- **They are evidence, not law.** Anything marked "proposed", "provisional" or "not approved" is a proposal. Do not treat it as
  decided. If you need it, propose it and record the outcome in `decisions.md`.
- **Values come from the snapshot, not from the reports.** Generators read `design/figma/<snapshot>/` (D-008). Use the reports
  to cross-check counts and naming: 282 variables, 63 text styles, 104 icons × 2 styles. A mismatch is an erratum
  (`errata.md`); ask the owner.
- **A conflict with levels 1–3 is not yours to resolve.** Follow levels 1–3, log the conflict in `errata.md`.
- **Large files.** The JSON registries are big (colors ≈ 195 KB, typography ≈ 50 KB). Do not read them whole; query them
  with `jq` or `grep`, or read the CSV.
- **Keep raw Figma names** (including source typos such as `Add Larg`, `Supportin Colors`, `Countainer/*`) in the mapping.
  Dart names use the corrected `snake_case` ids from the registry.
- **Colors:** Light and Dark are separate Figma collections, with no aliases. Semantic roles are not designer-approved.
  Do not assume `Primary/Pink` is the brand primary, or that a palette value equals a semantic role because the hex matches.
  Expose semantic roles on components, never the 242 primitives.
- **Icons:** Material Design 3 compatibility is not verified. Only 65 of 104 Outline/Fill pairs differ in shape. A missing style
  is an explicit diagnostic, never a silent substitute.
- **Typography:** pick a style by its full name `English/<Muted|Variant|Baseline>/<Role>-<Size>`, never by size or weight alone.
  Persian typography is pending (R-003).
- **Identity contract:** use v1.1 only. v1.0 is superseded and is not in the repo.

## Independent Viewer and motion revisions

D-021 authorizes engineering-defined shared Button press motion (not Figma motion); generate defaults from design/engineering/button_motion.json. D-022 authorizes bilingual Viewer localization and its persistent physical-left inspector. These do not expand product localization or product component scope. No golden baselines are authorized by this Viewer task.

D-023 authorizes the complete read-only icon extraction, shared full AppIcon registry
and original SVG assets, bilingual Icons tab and source-linked Button artwork.
Icon size/color and semantic/decorative API are explicitly allowed; original paint
is default and only monochrome artwork may be tinted. Never force a missing pair,
strip SVG features or claim source approval/license metadata that is unavailable.
Pure icon artwork exposes its generated logical/source identity through the
registry; the consuming control owns ElementIdentity/runtime locator and semantics
(D-023), so artwork does not invent or duplicate an interactive control identity.
